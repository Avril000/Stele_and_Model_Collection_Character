## 二、⚠️ 第一件事：一个必须现在就知道的坑

文档第三步让大家 `cd /home/ubuntu/guji-jiaocuo` 然后 `nano app.html` 改代码——

**那是古籍系统（服主/老师的项目）的目录，不是我们的。**

如果每个同学都照着这一步在那个目录里改 `app.html`，结果是：**全班互相覆盖，古籍系统被改坏。**
文档自己也写了"密码不要外传，否则你有概率抹杀他人作业"。

### 我们的规则

1. **绝不进入、绝不修改 `/home/ubuntu/guji-jiaocuo` 下任何文件**
2. 我们只在**自己的目录**里工作（见下方"我们的目录"）
3. `sudo guji-restart.sh` 是重启古籍系统的命令，**跟我们无关**，不要执行

> 正确做法在文档后半段其实写了：「在服务器上建个自己的文件夹（mkdir myweb）」。前半段只是演示步骤，容易误读。

## 三、判断：用，但用「双轨制」

### 结论

| 轨道 | 形态 | 地位 |
| --- | --- | --- |
| **主轨（必须有）** | 本地零依赖网页，双击 `web/index.html` | **演示主力，永远可用** |
| **副轨（锦上添花）** | 服务器在线版 `http://81.71.14.93:5019/` | 现场能开就开，打不开立刻切主轨 |

### 为什么是双轨，而不是"直接部署到服务器"

| 风险 | 说明 |
| --- | --- |
| 🔴 共享账号，全班同一密码 | 拿到密码的人理论上能动我们的文件。**服务器不能当唯一副本** |
| 🔴 端口要服主手动放行 | 我们开不了防火墙，依赖别人，有延迟 |
| 🟡 稳定性未知 | 2核4GB 十几个人共用，汇报当天别人跑重东西我们就卡 |
| 🟡 教室网络未必通 | 校园网能否访问公网服务器是未知数，现场可能打不开 |
| 🟡 进程可能悄悄挂掉 | 静态服务进程退出后网页就没了，不检查发现不了 |

**结论：在线版是加分项，不是保命项。保命的是本地那份。**

### 一个意外的好消息：这个决定恰好印证了方案 C

我们选定的方案 C，成品就是一堆**纯静态文件**（HTML + 图片 + JSON）。

这意味着：**同一份文件，既能本地双击打开，又能原样丢到服务器上跑起来，零改动。**

```
        ┌─► 本地双击 index.html          （主轨，永远可用）
同一份
静态文件┤
        └─► 服务器 python3 -m http.server （副轨，在线加分）
```

如果当初选的是 Flask 后端方案，就得维护两套、部署两次，还多一堆环境依赖。
**服务器这条信息，是把方案 C 从"推荐"变成"更确定"的最后一块拼图。**

## 四、三个用法，按价值排序

### 用法 1（推荐）：在线展示 —— 汇报现场的加分项

- 现场说一句"这个作品也部署在服务器上，大家可以扫码看"，效果很好
- 甚至可以让老师当场点开看
- **但 PPT 和演示流程必须假设它打不开**，以本地版为准

### 用法 2（谨慎）：团队协作环境 —— 可选

- 5 人共用一个地方跑脚本，环境统一
- 但对新手来说，SSH + nano + 端口这套东西要花时间学，可能拖慢主线
- **建议：不做硬性要求，谁有兴趣谁来玩**

### 用法 3（待评估）：用服务器网络跑数据抓取

- 服务器在腾讯云，外网访问能力可能强于校园网
- 理论上可以在服务器上批量下载碑帖图像，绕过校园网限制
- ⚠️ **两个前提**：① 服务器确实能访问目标站点（需实测）② 不能跑太重，会影响别人
- **建议：等 W2 数据组发现本地下载受阻时，再启动这个方案。** 不要一开始就依赖它

### 不建议的用法

- ❌ 当备份用（GitHub 才是正本）
- ❌ 当代码仓库用（版本管理还是要靠 Git）
- ❌ 部署需要 Flask / 后端的东西（徒增复杂度）

## 六、操作步骤（2026-11-08 订正：平时只需双击 bat）

> **正规入口是根目录的「一键_部署到服务器.bat」**，它做三件事：打包 → 上传 →（没在跑才）起服务 → 本机探测。
> 下面这一节留着当**手工兜底**：万一 bat 跑不通、或者要在一台没装本项目的机器上操作，照着敲。
> 长庚不在你授权的情况下自行连接服务器。

### 0. 端口

最终端口 **5721**（服主 刘文钊 已放行）。历史备选：5019 / 5119 / 5219。

### 1. 建自己的目录

```bash
ssh guji@81.71.14.93
pwd                      # 先确认自己的家目录，不要在 guji-jiaocuo 里操作
mkdir -p ~/jizi-19
cd ~/jizi-19
```

### 2. 上传文件（在本地 PowerShell 执行，不是在服务器上）

```powershell
scp .\web\index.html .\web\style.css .\web\app.js .\web\data.js guji@81.71.14.93:~/jizi-19/
```

> 只传这四个就够。`web/glyphs/` 那 8 MB 是别的流程用的，字形图已经 base64 嵌进 `data.js`，
> 服务器上一份都不用传（少传 8 MB，也少一次等待）。

### 3. 起静态服务（纯静态，不需要 Flask）

```bash
cd ~/jizi-19
(nohup python3 -m http.server 5721 --bind 0.0.0.0 > server.log 2>&1 < /dev/null &)
```

### 4. 验证（两步，别混着猜）

```bash
ss -lntp | grep ':5721'          # 服务器上有没有在听 ← 服务真在不在跑
```
```powershell
Test-NetConnection 81.71.14.93 -Port 5721   # 在本机执行 ← 外面通不通（这条才是防火墙的判据）
```

> **两个判据分开**：服务器上没在听 = 服务没起来（看 `server.log`）；
> 服务器上在听、本机不通 = 才是防火墙/安全组的事，这时候找服主才有据可依。

### 5. 换了文件要重启吗？——**不要**

`python3 -m http.server` 是静态服务，**每次请求都从磁盘读文件**。传完新文件，刷新浏览器就是新版，
根本不用重启。重启唯一的作用是打断正在看的人。

真要重启（换端口、换目录、进程僵死）时，用脚本的 `--restart`：

```powershell
python tools\deploy_server.py --restart
```

> ⚠️ **2026-11-08 的血账**：以前这里写的是 `pkill -f "http.server 5721"` 接 `nohup ... http.server 5721`。
> `pkill -f` 匹配的是**整个命令行**，而这条命令的后半截就含 `http.server 5721` 这串字面量，
> 于是 pkill 匹配到了**执行它的那个 shell 自己**，把自己杀了——返回码 `-1`（Windows 上显示
> `4294967295`），后面的启动命令一次都没执行过。**所以 10-24 到 11-07 那几次"端口起不来"，
> 全是我们脚本自杀，不是防火墙。** 教训：`pkill -f` 只要和字面量出现在同一条命令里，
> 加方括号 `[h]ttp` 也救不了；正确做法是**把「杀」和「起」拆成两条命令**，或者干脆不杀。

> 注意：**不需要** `sudo guji-restart.sh`，那是古籍系统的。

## 九、访问体验：为什么第一次慢、为什么浏览器说不安全

> 2026-11-08 实测记录。这两条**都不是 bug**，是"HTTP + IP + 单文件 11.5MB"这个组合的必然结果。

### 1. 第一次打开特别慢——正常的，卡在带宽上

| 环节 | 实测 | 说明 |
| --- | --- | --- |
| `data.js` | **11.47 MB** 单个文件 | 字形图全部 base64 内嵌，所以它一个文件就是整个字库 |
| gzip 后 | **6.83 MB（60%）** | `python -m http.server` **默认不发 gzip**，所以走的是 11.47 MB 原文 |
| 服务器带宽 | 1 Mbps ≈ **92 秒**；3 Mbps ≈ 31 秒；5 Mbps ≈ 18 秒 | 这一项才是决定性的，腾讯云学生机通常是 1~5 Mbps |

**为什么有的浏览器第二次就快、有的每次都一样慢**：`http.server` 只发 `Last-Modified`，
**不发 `Cache-Control`**，浏览器只能"启发式缓存"（自己估个新鲜期）。估得准的（Edge、部分国产浏览器）
就磁盘缓存命中、秒开；估不准的（Chrome 对超大 JS 常这样）每次都要回服务器校验、甚至重下——于是"一样慢"。

**怎么办（按成本排）**：

1. **预热**：演示/发链接前自己先打开一次，等你到现场时浏览器已经有缓存了（最省事，零改动）；
2. **演示用主轨**：本地双击 `web/index.html`，0 等待、0 网络；服务器版只发给组员"玩"；
3. 想真的变快：给静态服务加 gzip + `Cache-Control: max-age=31536000`
   （换一个几十行的标准库小服务即可，二次访问接近瞬间，但第一次仍受带宽限制）；
4. 想根本解决：把 `data.js` 拆成"索引 + 按字懒加载"，工程量中等，**会破坏"单文件双击即开"的设计**，
   不建议在课程周期内动。

### 2. 浏览器报"不安全/可能有诈骗风险"——正常的，因为没有 HTTPS

- 我们是 `http://IP:端口`，**明文传输、没有证书、端口不是 443**。Chrome/Edge 地址栏标"不安全"是标准行为，
  点「高级 → 继续前往」即可；
- 那种带"诈骗风险/危险网站"红屏的，多半不是浏览器内核拦的，而是**国产安全软件或少部分浏览器的网址云查杀**：
  无备案、无域名信誉、无 HTTPS，再加上一次性静默拉 11.5 MB 资源——评分低就被拦了；
- **从安全实质看我们很干净**：纯静态页，没有表单、没有 cookie、没有登录、没有第三方脚本，
  数据全在自己仓库里。被拦是"身份不明"，不是"行为可疑"；
- **怎么处理**：① 演示用 Chrome/Edge，别用 360/QQ 浏览器；② 提前点过一遍"继续访问"（浏览器会记住例外）；
  ③ 跟老师/组员一句话说明"这是班级服务器，IP 直连没有证书，提示不安全点继续就行"；
- **想彻底消除**：需要域名 + 证书 + 443 端口，班级服务器给不了。备选是挂 GitHub Pages（自带 https），
  但校园网访问 `github.io` 不稳，**为课堂演示不值得折腾**。

## 九、关于长庚要不要直接连服务器

**建议：第一阶段先不连。**

理由：

1. 现在上去没什么可部署的，只有风险没有收益
2. 共享服务器影响面大，多一个持有密码的人就多一分风险（文档明确要求不外传）
3. 学 SSH 本身是很好的练习，正好给队友当 Git 之外的第二项技能

**等你决定**：如果 W2 之后你希望我来部署，我可以上——但我会**只在 `~/jizi-19` 目录内操作，绝不碰其他任何地方**，每一步做什么都先告诉你。
另一种更安全的做法：**我不连，我给你命令，你在自己电脑上敲**，出错了把报错原文贴给我。

## 十、现在怎么部署（2026-10-24 更新：已经做成一键了）

第六节里那些命令现在是脚本了，**不用再手敲**：

```
双击「一键_部署到服务器.bat」
  → 问端口（服主给你的那个，自己填，脚本不预设）
  → 自动打包（只收网页真正需要的 4 个文件，6 MB）
  → scp 上传（问一次密码）
  → ssh 起静态服务（再问一次同一个密码）
  → 打印访问地址
```

### 打包时会丢掉什么、为什么没关系

| 内容 | 大小 | 处理 |
| --- | --- | --- |
| `index.html` `style.css` `app.js` `data.js` | 6.1 MB | **要传** |
| `web/glyphs/` | 8.6 MB | **不传**——字形图已以 base64 嵌进 data.js，网页运行根本不读这个目录 |

所以服务器上的完整站点只有 6 MB，上传快，加载也不卡。

### 安全上的三个刻意设计

1. **端口不预设**：脚本里不写任何端口号，每次运行时由白星当场填。
   填过的会记在 `deploy_config.json`，但这个文件已加进 `.gitignore`，不会进仓库。
2. **密码一次都不存**：由 `scp` / `ssh` 在窗口里当场问，敲完就消失。
   脚本和配置文件里都没有密码字段。
3. **只在 `~/jizi-19` 里动手**：`pkill` 也只杀我们自己的 `http.server 端口` 进程。

### 想省掉每次输两次密码（可选）

在服务器上配一次 SSH 公钥免密登录，之后 bat 就可以全自动了。
要做的话跟长庚说一声，我给你三条命令。
